# Design system playbook — Legendary Shots

This playbook explains **how** to build Legendary Shots screens with the design system: which elements to use, when,
and what to avoid. The visual charter (colours, identity, contrast rules, responsive) is defined in
`docs/07-design.md`; the mockups in `docs/design/` are a visual reference, never code to copy.

## Principles

1. **Captures first.** The interface stays in the background: night-blue background, thin frames, few ornaments. A
   photo is never covered by interface without a scrim.
2. **Nuit d'Azeroth.** Dark theme only, gold (`--color-accent`) for the main action and strong titles, Cinzel for
   titles, Inter for text. WoW codes (quality, quest markers, item tooltip) are drawn in-house, never taken from the
   game.
3. **Mobile first.** Everything works at 360 px wide; screens get richer beyond (768, 1024, 1280 px).
4. **Accessible by construction.** AA contrast, keyboard, 44 px targets, reduced motion: see the Accessibility page.
5. **Tokens, never values.** A colour, a size or a spacing comes from a variable of `tokens.css`; Stylelint refuses
   anything else.
6. **No empty block.** A module without content shows a useful empty state (EmptyState) or disappears.

## Organisation (atomic design)

| Level       | Where                                   | Examples                                    |
| ----------- | --------------------------------------- | ------------------------------------------- |
| Foundations | `app/assets/css/tokens.css`, `base.css` | colours, typography, spacing                |
| Atoms       | `app/components/ui`                     | Button, ActionIcon, Input, LogoMark         |
| Molecules   | `app/components/ui`                     | Card, EmptyState, Modal, BottomSheet, Toast |
| Organisms   | `app/features/<feature>/`               | capture grid, upload form                   |
| Templates   | `app/layouts`                           | layout with header and footer               |
| Pages       | `app/pages`                             | home page, photo page                       |

Components in `app/components/ui` are pure presentation: they receive props, emit events and never call the API.
